# 日付の切り替わり

CHUNITHMの「今日」と「現行バージョン」は、暦日の0時ではなく **日本時間（JST）7:00** に切り替わります。店舗の日替わりと、新バージョンの稼働開始に合わせた定義です。

実装は `internal/domain/gamedate` にあります。APIはこのパッケージだけを使い、7時や「7時間引く」を別の箇所に書かないでください。

**フロントエンドも同じ定義を使ってください。** 「今日」、現行バージョン、スコア履歴のバージョン境界、新曲枠の理論値に使う現行バージョンを、暦日の0時（`T00:00:00+09:00`）で決めると、稼働日の0:00〜7:00にAPIと表示がずれます。

## 今日（運用日）

日本時間の壁時計から7時間引いた暦日を、その時点の「今日」とします。再計算バッチの運用日もこの日付です。

| 時点 | 今日 |
| --- | --- |
| 日本時間 2026-07-06 06:59:59 | 2026-07-05 |
| 日本時間 2026-07-06 07:00:00 | 2026-07-06 |

## 現行バージョン

バージョンの稼働日は日付（`YYYY-MM-DD`）で持ちます。そのバージョンが現行になるのは **稼働日の日本時間7:00** です。7:00未満は直前のバージョンが現行です。

| 時点（稼働日が 2026-07-06 の新バージョン） | 現行 |
| --- | --- |
| 日本時間 2026-07-06 00:00:00 | 直前のバージョン |
| 日本時間 2026-07-06 06:59:59 | 直前のバージョン |
| 日本時間 2026-07-06 07:00:00 | 新バージョン |

次の判定はすべてこの時刻です。

- 公開バージョン一覧。マスタの公開ビュー、`GET /internal/master` と `GET /internal/master/versions` の `versions`、`GET /v1/master/versions`、reiwa互換の `chunithm_versions.json`、静的書き出しのバージョンJSON
- 再計算バッチが「現行バージョン」として読むバージョン。運用日以前に稼働した最新バージョン
- 現行プレイヤーの判定。最終プレイ日時が、現行バージョン稼働日の日本時間7:00以降であること

管理APIのバージョン一覧は、未来版を含めて全件を返します。公開判定には使いません。

## 新曲

再計算バッチの新曲判定は、現行バージョンの稼働日以降、かつ運用日以前に公開された楽曲と、公開日未設定の楽曲です。楽曲のリリース日も日付だけです。運用日が7:00に切り替わった時点で、その日の楽曲を公開済みとして扱います。`songs.is_new` は使いません。

## この定義を使わないもの

次は日付の切り替わりではなく、保存された暦日の表現です。7:00にはしません。

- APIが返す `released_at`。稼働日の日付のままで、時刻を7:00にはしません
- reiwa互換の楽曲 `release`。リリース日の日本時間0時のUnixタイムスタンプを100で割った互換形式です
- 楽曲データ収集バッチの `--fill-missing-release-date`。日付が得られない新規楽曲へ、実行時点の日本時間の暦日（0時切り替え）をリリース日として補完します。7時前に前日の日付を書くと、まだ配信されていない楽曲が運用日上は公開済みになるためです
