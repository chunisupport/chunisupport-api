# 譜面統計バッチ（chart-stats-batch）

プレイヤーの譜面別記録をベスト枠平均レーティング帯ごとに集計し、公開APIが参照する統計テーブルを再構築するバッチです。
以前は `chunisupport-stat-batch` リポジトリで管理していましたが、API リポジトリへ統合しました。集計規則は [譜面統計バッチの集計仕様](chart_statistics_aggregation.md) を参照してください。

## 実行方法

```bash
go run ./cmd/chart-stats-batch
```

引数はありません。旧 stat-batch の `--dry-run` は廃止しました。付けたまま実行すると統計を書き換えてしまうため、引数を指定した場合は終了コード 2 でエラー終了します。

設定は他のバッチと同じく `config.LoadBatchConfig()` で読み込みます。統合前の stat-batch とは次の点が異なります。

- `APP_ENV` が必須です（未設定時に `develop` として扱うことはしません）。`.config/<APP_ENV>.settings.json` と DB 接続用の環境変数も必要なため、cron では API のディレクトリで実行してください。
- ログの出力先は標準出力固定ではなく、設定ファイルの `logging` に従います。
- 実行履歴を `chart_stats_batch_jobs` テーブルへ記録するため、マイグレーション `000054` を適用してから新しいバイナリを使ってください。
- 不正利用疑いのユーザーを譜面統計・WORLD'S END 譜面統計からも除外します（旧 stat-batch ではベスト枠採用率からだけ除外していました）。そのため、切り替え後の初回実行で統計の値が変わることがあります。

### cron の設定例

API と同じアーティファクトに同梱され、API のディレクトリへ展開されます。設定ファイルと `.env` を読み込むため、API のディレクトリで実行してください（スケジュールは運用に合わせて設定します）。

```cron
0 4 * * * cd /home/ubuntu/apps/chunisupport/api && ./chunisupport-chart-stats-batch-linux-amd64
```

### 旧 stat-batch からの切り替え

旧 stat-batch と新しいバッチは多重起動防止のロック名が異なり（旧: `chunisupport:stat-batch:<DB名>`、新: `chunisupport:chart-stats-batch`）、互いの実行を止めません。
両方が同時に動くと統計テーブルへの書き込みが競合するため、旧 cron が有効な期間と、新しい API（管理画面からの実行）・新 cron が有効な期間を重ねないでください。

1. マイグレーション `000054` を適用する
2. 旧 stat-batch の cron 行を削除する
3. 新しい API とバッチをデプロイする
4. 新しい cron 行を登録する
5. 旧 stat-batch のバイナリと設定（`/home/ubuntu/apps/chunisupport/statbatch/`）を削除する

## 管理APIからの実行

ADMIN は管理画面向けの API `POST /internal/admin/chart-stats-batch/jobs` から、CLI と同じ処理を任意のタイミングで実行できます。API は要求を受け付けると、API プロセス内でバックグラウンド実行します（仕様は [API.md](API.md) を参照）。

- CLI と管理画面は同じアドバイザリロックを使うため、同時に実行される譜面統計バッチは常に1つです。管理画面からの要求は、実行中なら `409` で拒否します。
- API の停止時に実行中だったジョブはキャンセルされ、統計テーブルの入れ替えはロールバックされます。
- 公開用の統計JSON（`export-static-data --chart-stats`）は、R2 へのアクセスを抑えるため定期実行で更新し、このバッチからは更新しません。管理画面から再集計しても、統計JSONへの反映は次回の定期実行までかかります。API の統計エンドポイントには再集計の直後から反映されます。

## 実行履歴

CLI・管理画面のどちらから実行した場合も、`chart_stats_batch_jobs` テーブルへ実行履歴を記録します（ロック競合でスキップした実行は記録しません）。保持するのは最新50件までで、新しいジョブを記録した時点でそれより古いジョブを削除します。管理APIも最大50件を返します。

| 状態 | 意味 |
| --- | --- |
| `RUNNING` | 実行中 |
| `SUCCEEDED` | 統計テーブルを再構築した |
| `FAILED` | 失敗。統計テーブルは更新されていません |
| `INTERRUPTED` | プロセス停止などで中断（下記参照） |

実行中にキャンセルされて `INTERRUPTED` になった場合、統計テーブルの入れ替えはロールバック済みです。
プロセスが異常終了して `RUNNING` のまま残った行は、次に譜面統計バッチがロックを取得したときに `INTERRUPTED` へ更新します。この場合は入れ替えのコミット直後に停止した可能性もあるため、入れ替えの成否は不明です。

## 処理フロー

1. **ロック** – 全起動経路（CLI・管理画面）で MySQL アドバイザリロック `chunisupport:chart-stats-batch` を取得します。取得できない場合、CLI はスキップ（終了コード 0）します。
2. **集計元の読み取り** – レーティング帯を読み込んだ後、通常譜面・WORLD'S END 譜面の記録とベスト枠採用率の集計元を、読み取り専用の単一 REPEATABLE READ スナップショットから1行ずつ読み取ります。
3. **集計** – 譜面統計は記録を譜面ID順に受け取り、譜面が切り替わった時点でその譜面の集計を確定します。中央値のために保持するスコアは1譜面分だけです。
4. **入れ替え** – 3つの統計テーブルを単一トランザクション内で削除・挿入します。コミットまでは直前の統計が見え続け、失敗やキャンセル時はロールバックされるため、統計が空または途中までの状態は公開されません。

処理件数（読み取った記録数、書き込んだ統計行数）は完了時のログに出力します。

## コード構成

| パス | 内容 |
| --- | --- |
| `cmd/chart-stats-batch` | CLI のエントリーポイント（DB 接続、ジョブ実行） |
| `internal/domain/chartstatsbatch` | 集計規則（ランク・ランプの分類、平均・中央値、ベスト枠採用率） |
| `internal/usecase/chart_stats_batch_usecase.go` | 集計元の読み取り・集計・統計テーブルの入れ替え |
| `internal/usecase/chart_stats_batch_job_usecase.go` | ロック取得、実行履歴の記録、管理画面からのバックグラウンド実行 |
| `internal/infra/repository/chart_stats_batch_repository_impl.go` | 集計元のストリーミング読み取りと統計テーブルの入れ替え |
